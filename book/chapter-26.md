# Часть VII. Производительность

## Глава 26. Оптимизация JavaScript

К 2026 году парадигма оптимизации JavaScript вышла на новый технологический уровень благодаря глубокой интеграции инфраструктурных инструментов на базе Rust и утверждению концепции *ESM-first*. Фокус индустрии сместился с простого уменьшения размера файлов на интеллектуальное управление ресурсами, где цель компилятора — доставить в браузер ровно те байты и строго в тот момент времени, которые необходимы для выполнения текущего сценария пользователя.

---

### Bundling: эра нативных Rust-сборщиков

Инструменты сборки нового поколения оставили позади медленные JavaScript-решения, обеспечив заметный прирост производительности:

* **Bun:** предлагает встроенный высокопроизводительный бандлер, выступая одновременно как среда выполнения, менеджер пакетов и инструмент сборки — по независимым бенчмаркам его сборщик заметно опережает классические JS-инструменты на проектах любого масштаба, хотя точный выигрыш сильно зависит от конкретного кода и конфигурации.
* **Rolldown:** Rust-бандлер, совместимый с плагинным API Rollup и нацеленный на паритет производительности с esbuild при сохранении возможностей полноценного бандлера. Он лёг в основу Vite, начиная с восьмой версии фреймворка (стабильна с марта 2026 года), заменив собой прежнюю связку esbuild (для разработки) и Rollup (для продакшн-сборки) единым движком.
* **Rspack:** высокопроизводительная альтернатива Webpack, написанная на Rust и сохраняющая совместимость с значительной частью его экосистемы плагинов и лоадеров, что упрощает миграцию legacy-проектов.

---

### Tree Shaking и статический анализ кода

Механизмы очистки кода от балласта стали заметно интеллектуальнее:

* **Tree Shaking:** современные сборщики (включая Rspack и Rolldown) выполняют статический анализ графа зависимостей, автоматически отсекая неиспользуемые экспорты из библиотек.
* **Dead Code Elimination:** JS-компиляторы вроде SWC и Oxc (используемого, в частности, в связке с Rolldown) вырезают «мёртвые» ветки кода, константы и невызываемые функции на этапе трансформации. Отдельно от этого Lightning CSS решает похожую задачу для стилей — минифицирует и оптимизирует CSS, — но это два разных инструмента для двух разных языков, а не взаимозаменяемые альтернативы.

---

### ESM-first и нативная модульность

К 2026 году стандарт ECMAScript Modules (ESM) закрепился в статусе фундаментальной основы веб-разработки:

* **Dev Server на ESM:** инструменты вроде Vite отдают исходные модули браузеру по требованию (*on-demand*), в значительной мере избавляя от долгой предварительной сборки при старте сервера разработки.
* **Современные рантаймы:** среды Deno и Bun спроектированы вокруг ESM-модели, обеспечивая удобное подключение пакетов из реестров и встроенную поддержку TypeScript без отдельных транспайлеров.

---

### Dynamic Import и стратегия Code Splitting

Автоматическое разделение кода (*code splitting*) интегрировано на уровне самих фреймворков и сборщиков:

* Использование динамических импортов (`import()`) позволяет делить приложение на изолированные чанки, подгружаемые по мере необходимости (*on-demand loading*).
* Этот подход важен для достижения целевых показателей LCP и INP, так как браузер освобождается от необходимости скачивать и парсить гигантские монолитные скрипты при старте.

---

### Import Maps и безъядерная структура

Стандарт **Import Maps** позволяет браузеру напрямую сопоставлять логические имена модулей с их реальными URL без необходимости использования сложных бандлеров на этапе разработки. Это открывает дорогу к архитектурам вида *node_modules-less*, где сторонние зависимости подгружаются напрямую из глобальных кэшей или специализированных CDN-реестров (например, JSR), заметно ускоряя инициализацию проектов.

---

### Module Federation: архитектура микрофронтендов

Технология **Module Federation** стала одним из стандартов де-факто для построения распределённых enterprise-систем и микрофронтендов:

* Встроенная поддержка на уровне Rspack и Webpack позволяет независимым командам разрабатывать, деплоить и обновлять изолированные части единого интерфейса параллельно.
* Приложения могут динамически обмениваться скомпилированными модулями в рантайме, совместно используя общие библиотеки (например, React или дизайн-систему) без дублирования кода в бандлах.

Оптимизация JavaScript в современных реалиях представляет собой слаженную экосистемную оркестрацию, где компиляторы на Rust и нативные возможности браузеров работают в тесном симбиозе для достижения высокого быстродействия.
