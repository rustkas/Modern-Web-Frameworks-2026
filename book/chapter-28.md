# Часть VIII. Full Stack

## Глава 28. Server Functions

К 2026 году грань между клиентским и серверным окружением в веб-разработке стала практически неразличимой. Инженерам больше не требуется вручную проектировать громоздкие REST или GraphQL контракты для каждого элемента интерфейса. На смену им пришла концепция **Server Functions** (серверных функций) — элегантный парадигматический сдвиг, позволяющий писать бэкенд-логику в виде обыкновенных асинхронных функций, вызываемых напрямую из клиентского кода.

---

### RPC (Remote Procedure Call) сквозь призму компилятора

В основе Server Functions лежит проверенная временем модель **RPC (удаленный вызов процедур)**, переосмысленная на уровне современных компиляторов:

* **Сквозная типизация (End-to-End Type Safety):** Ведущие full-stack фреймворки (Astro, SvelteKit, Next.js, SolidStart) обеспечивают бесшовную передачу типов через сетевой барьер. Если сигнатура серверной функции претерпевает изменения, система мгновенно фиксирует нестыковку на стороне клиентского компонента.
* **Автоматизация эндпоинтов:** Инфраструктура сборки самостоятельно анализирует код, генерируя необходимые сетевые маршруты и сериализаторы в фоновом режиме, полностью избавляя разработчика от рутинной маршрутизации API.

---

### Actions: Безопасность и Server-first подход

Инструменты управления мутациями (известные в экосистеме React как *Server Actions*) стали отраслевым стандартом выполнения логики на стороне бэкенда:

* **Изоляция среды:** Выполнение кода строго на сервере гарантирует безопасный доступ к базам данных, защищенным ORM и конфиденциальным API-ключам без риска их утечки в клиентский бандл.
* **Zero Bundle Size:** Тела серверных функций полностью исключаются из клиентской сборки, что кардинально снижает объемы загружаемого JavaScript.

---

### Мутации данных и управление состоянием

Server Functions выступили основным инструментом для работы с побочными эффектами и изменениями данных:

* **Интеграция с кэшем и ревалидация:** Сразу после выполнения мутации (например, отправки заказа или редактирования профиля) фреймворк производит автоматическую инвалидацию затронутых кэш-тегов, синхронизируя интерфейс за один сетевой цикл.
* **Устранение boilerplate-кода:** Отпала необходимость вручную управлять флагами загрузки, промежуточными store-состояниями и дублировать валидацию на обеих сторонах.

---

### Нативные формы и синергия с HTML

Современные серверные функции раскрывают свой максимум в плотной связке со стандартными HTML-формами, возвращая разработчиков к классическим веб-примитивам через атрибут `action`:

* **Автоматическая сериализация:** Фреймворк берет на себя сбор данных из элементов формы в стандартный объект `FormData`, передавая его в качестве аргумента типизированной серверной функции.
* **Серверная валидация:** Проверка входных данных происходит на бэкенде, а структурированные отчеты об ошибках возвращаются прямо в UI для отрисовки без написания громоздких клиентских валидаторов.

---

### Progressive Enhancement: Возвращение надежности

Широкое распространение Server Functions возродило философию **Progressive Enhancement (постепенное улучшение)** в масштабах современной индустрии:

* **Отказоустойчивость:** Если клиентский JavaScript заблокирован, еще не загружен или отключен пользователем, приложение не теряет работоспособности — форма штатно отправляется по стандартному протоколу браузера с обновлением страницы.
* **Мгновенный UX:** Как только гидратация завершена, фреймворк перехватывает событие отправки, превращая жесткий запрос в быстрый асинхронный вызов без перезагрузки интерфейса, используя ту же самую серверную логику.

Server Functions в 2026 году окончательно превратили веб в единую целостную среду, где инженеры концентрируются исключительно на бизнес-логике, делегируя инфраструктурной платформе всю сложность сетевой оркестрации.
