# Часть VIII. Full Stack

## Глава 30. Full Stack Frameworks

К 2026 году грань между фронтенд-библиотеками и серверной инфраструктурой заметно стёрлась. Современные **full stack фреймворки** трансформировались в самодостаточные экосистемные платформы, которые под ключ закрывают задачи рендеринга интерфейсов, сквозного управления данными, изоляции контекстов безопасности, оптимизации ресурсов и деплоя на «краю» сети (edge). Доминирующим парадигматическим стандартом стал подход server-first, при котором бэкенд берёт на себя значительную часть вычислительной нагрузки, доставляя на клиентское устройство минимально необходимый объём исполняемого кода — хотя, как показывает пример TanStack Start ниже, у индустрии есть и заметные client-first альтернативы.

---

### Next.js: флагман React-экосистемы

Next.js прочно удерживает лидерские позиции, предлагая одну из наиболее зрелых интеграций с передовыми возможностями React:

* **App Router и RSC:** архитектура на базе React Server Components позволяет расширять функциональность приложений, ограничивая рост клиентского JavaScript-бандла.
* **Server Actions:** механизм прямого вызова серверных процедур из клиентских компонентов с автоматической инвалидацией кэша и ревалидацией.
* **Partial Prerendering (PPR):** симбиоз статической доставки каркаса через CDN и потокового рендеринга интерактивных компонентов, стабилизировавшийся в Next.js 16 как часть архитектуры Cache Components.
* **Производительность:** связка с компилятором Turbopack (на Rust), стабильным и используемым по умолчанию с той же версии, помогает удерживать хорошие показатели Core Web Vitals.

---

### Nuxt: универсальный комбайн Vue-индустрии

Nuxt закрепил за собой статус одной из главных full-stack платформ для Vue-разработчиков, опираясь на возможности серверного движка Nitro:

* **Hybrid Rendering:** гибкая настройка стратегий доставки контента (SSR, SSG, ISR) на уровне отдельных маршрутов приложения.
* **Nuxt Islands:** изоляция интерактивных блоков разметки для снижения нагрузки на клиентский поток и улучшения метрики INP; часть смежных возможностей (в частности, Vue Server Components) на момент написания книги остаётся экспериментальной, как обсуждалось в главе 24.
* **Edge-совместимость:** переносимость приложений между большинством serverless- и периферийных платформ без глубокой переработки кодовой базы.

---

### Remix и React Router: слияние, а не просто интеграция

Здесь важно точно передать то, что произошло с Remix, потому что формулировка «интегрирован с React Router» смазывает суть события: в 2024 году команда Remix объявила, что классический Remix **сливается с React Router**, а не просто с ним взаимодействует, — и вышел как React Router v7. Разработчики, использующие React Router 7 в режиме Framework Mode, по сути получают возможности Remix: серверный рендеринг, продвинутую загрузку данных через loaders, вложенную маршрутизацию и опору на нативные браузерные примитивы (`Request`, `Response`, `FormData`). Отдельно от этого команда (при поддержке Shopify) развивает **Remix 3** — переосмысление проекта уже не как надстройку над React Router, а как самостоятельный, «батарейки в комплекте» фреймворк без обязательного этапа сборки бандлером. Это два разных, параллельно существующих проекта под частично общим именем, и важно не путать их при выборе стека.

### SvelteKit: минимализм и Zero Runtime

Текущая стабильная линейка **SvelteKit — 2.x**, построенная поверх ядра Svelte 5 с его системой рун:

* **Интегрированная обсервабельность:** поддержка мониторинга через интерфейсы вроде `instrumentation.server.ts` для анализа работы приложений в продакшене.
* **Remote Functions:** типизированные серверные функции и развитая валидация форм упрощают проектирование full-stack решений — но, как отмечалось в главе 19, часть смежных возможностей (например, полноценный streaming в асинхронном SSR) пока остаётся экспериментальной.

---

### Qwik City: ставка на мгновенную Resumability

Мета-фреймворк для Qwik, спроектированный вокруг концепции возобновляемости:

* **Минимум JavaScript по умолчанию:** приложения стартуют без прохождения тяжёлых циклов гидратации, загружая код обработчиков точечно в момент реального взаимодействия пользователя с элементом — с оговорками о цене этого подхода, разобранными в главе 20.
* **Edge-оптимизация:** хорошая совместимость со средами выполнения вроде Cloudflare Workers и Deno Deploy за счёт небольших серверных накладных расходов.

---

### Astro: эталон контентно-ориентированного full stack — теперь под крылом Cloudflare

Astro прочно удерживает позиции лидера в сегменте медийных, корпоративных и коммерческих сайтов с высокой плотностью контента, а 16 января 2026 года в его истории произошёл значимый корпоративный поворот: команда The Astro Technology Company присоединилась к **Cloudflare**. Фреймворк остаётся open source под лицензией MIT, а команда продолжает работу над ним в прежнем составе — но теперь при поддержке инфраструктуры и ресурсов Cloudflare, что укрепляет и без того тесную интеграцию Astro с Cloudflare Workers. Незадолго до сделки был анонсирован бета-релиз Astro 6 с поддержкой дополнительных JavaScript-рантаймов.

* **Content Collections:** типизированная работа с Markdown и MDX на этапе сборки с валидацией через схемы (Zod).
* **Server Islands:** интеграция динамических персонализированных блоков в статическую кэшируемую оболочку страницы.

### Архитектуры нового поколения: RedwoodSDK и TanStack Start

* **RedwoodJS → RedwoodSDK:** изначальный RedwoodJS был опинионированным full-stack фреймворком на GraphQL и Prisma, но в 2024 году команда сменила курс и занялась RedwoodSDK — ребилдом «с нуля», спроектированным специально под экосистему Cloudflare Workers, с нативной поддержкой D1 (база данных), R2 (объектное хранилище), Durable Objects, realtime API и React Server Components. Это не косметическое обновление, а смена архитектурной философии, поэтому при выборе Redwood для нового проекта в 2026 году стоит явно уточнять, о какой из двух версий идёт речь.
* **TanStack Start:** к середине 2026 года вышел из беты и достиг стабильного релиза 1.x, построен вокруг библиотек TanStack Router и TanStack Query. В отличие от большинства фреймворков из этой главы, TanStack Start сознательно не строится вокруг React Server Components — это, как уже обсуждалось в главах 9 и 28, client-first альтернатива server-first подходу, а не ещё одна его реализация.

Full stack фреймворки 2026 года заметно сблизили комфорт разработки и высокую производительность, объединив компиляторы, серверные примитивы и периферийные вычисления в общую среду — но, как показывают истории Remix/React Router, RedwoodJS/RedwoodSDK и приобретение Astro Cloudflare, ландшафт остаётся динамичным, и названия фреймворков сегодня не всегда означают то же самое, что и пару лет назад.
