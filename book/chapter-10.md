# Часть IV. Современные архитектуры

## Глава 10. Islands Architecture

Архитектура «островов» (Islands Architecture) в 2026 году утвердилась в статусе фундаментального ответа индустрии на системную проблему раздутого JavaScript в клиентских браузерах. В отличие от традиционных Single-Page Applications (SPA), где всё приложение по умолчанию привязано к единому монолитному бандлу, этот подход концептуально разделяет документ на стабильную неинтерактивную разметку и изолированные динамические модули. Страница по умолчанию является чистым HTML без JavaScript, и только точечные «острова» интерактивности получают клиентский код.

---

### HTML-First подход: Возвращение к основам платформы

Краеугольным камнем современной архитектуры стал принцип **HTML-First**, который возвращает гипертексту статус первоклассного гражданина веб-пространства. Это не отказ от JavaScript, а его стратегическое использование там, где он действительно нужен.

Архитектура строится вокруг структуры самого документа, а не вокруг сложного дерева клиентского JavaScript-состояния. Вместо того чтобы отправлять пустой HTML-скелет и ждать загрузки JS для рендеринга контента, сервер отдает полностью готовую страницу. Браузер пользователя мгновенно получает готовый к отрисовке контент, что радикально выправляет ключевые метрики производительности Core Web Vitals: First Contentful Paint (FCP) — время до первого контента; Largest Contentful Paint (LCP) — время загрузки основного контента; и Cumulative Layout Shift (CLS) — стабильность макета, которая не страдает от подгрузки JS-виджетов.

Интерактивные элементы внедряются инкрементально и точечно — исключительно в те зоны интерфейса, где это критически необходимо для пользовательского сценария. Если страница содержит слайдер, форму обратной связи и виджет корзины, только эти три «острова» получают JavaScript. Все остальное — заголовок, текстовые блоки, изображения, навигационные ссылки — остается статичным HTML. Это означает, что 80–95% страницы отправляется без JavaScript, что кардинально сокращает объем передаваемых данных и ускоряет загрузку.

### Astro: Флагман архитектуры островов

Фреймворк Astro прочно удерживает лидерство в сегменте инструментов для создания высокопроизводительных контентных и гибридных платформ. Ключевая концепция экосистемы звучит как «Zero JavaScript по умолчанию». Astro был первым фреймворком, который популяризировал Islands Architecture на широкую аудиторию, и остается эталонной реализацией этого подхода.

**Server-First компиляция.** Astro полностью исполняет компоненты на сервере, доставляя в браузер чистый, легковесный HTML без клиентских рантайм-накладных расходов. Это означает, что статические части страницы не содержат никакого JavaScript — только HTML и CSS. Процесс сборки Astro генерирует статические HTML-страницы по умолчанию, которые можно деплоить на любой CDN.

**Astro Islands.** Интерактивные мини-приложения («острова») могут быть написаны на абсолютно любых привычных UI-фреймворках (React, Vue, Svelte, Angular, Solid, Preact) и вмонтированы в единое статическое полотно страницы. Каждый остров изолирован от других: он не влияет на соседние компоненты, и его падение не ломает всю страницу. Это делает Astro идеальным для микросервисных подходов на фронтенде, где разные команды могут использовать разные фреймворки в рамках одного проекта.

**Тонкая настройка гидратации.** Разработчик получает декларативный контроль над триггерами активации через клиентские директивы. Например, указав директиву `client:visible`, можно приказать рантайму загрузить код компонента ровно в момент его попадания в поле зрения пользователя (viewport). Другие доступные директивы: `client:load` — гидратация сразу после загрузки страницы; `client:idle` — гидратация, когда процессор браузера переходит в состояние покоя (requestIdleCallback); `client:only` — компонент рендерится только на клиенте, никогда на сервере. Это позволяет точно контролировать приоритеты загрузки для каждого острова.

**Выдающиеся показатели производительности.** Типичный сайт на Astro отправляет на 80–95% меньше JavaScript, чем классическое SPA, и показывает почти идеальные метрики Core Web Vitals. Это делает Astro выбором по умолчанию для контентных сайтов, блогов, документации, интернет-магазинов и маркетинговых страниц. Начиная с версии 4.0, Astro также поддерживает Server Islands — серверные острова для персонализированного контента.

### Fresh: Острова в экосистеме Deno

Инновационный фреймворк Fresh, созданный сообществом Deno и поддерживаемый командой самого рантайма, предлагает уникальный взгляд на реализацию островной архитектуры с акцентом на простоту и скорость.

**Отказ от этапа сборки.** Проект полностью отказывается от традиционного этапа предварительной сборки (Build Step), выполняя компиляцию и JIT-рендеринг «на лету» средствами современной среды выполнения Deno. Это кардинально упрощает разработку: не нужно ждать сборки проекта при каждом изменении, горячая перезагрузка происходит мгновенно. Деплой также упрощается: можно загружать исходный код на сервер, и Deno будет компилировать его на лету.

**Изолированные острова через файловую систему.** Интерактивность обеспечивается через Preact — легковесную (3 КБ) альтернативу React. Код клиента автоматически генерируется и отправляется по сети только для тех компонентов, которые разработчик разместил в специальной директории `islands/`. Компоненты вне этой директории считаются статическими и никогда не получают JavaScript на клиенте. Это делает модель Fresh интуитивно понятной: разработчик просто кладет интерактивные компоненты в папку `islands/`, а все остальное автоматически становится статикой.

**Легковесность и производительность.** Fresh написан с нуля с учетом философии Deno — минимализм, безопасность и современные Web API. Он не требует конфигурации и предоставляет роутинг на основе файловой системы, встроенную поддержку TypeScript и автоматическую обработку форм. Это делает Fresh отличным выбором для небольших и средних проектов, которые хотят получить преимущества Islands Architecture без сложной настройки.

### Enhance: Стандарты и веб-компоненты

Enhance развивает HTML-first философию через глубокую опору на нативные стандарты спецификации Web Components и возможности веб-платформы, избегая привязки к конкретному фреймворку.

**Компоненты без фреймворка.** Инструмент полностью избегает навязывания тяжелых систем сборки, предлагая чистый функциональный подход к серверному рендерингу. Любой компонент здесь — это элементарная чистая функция, возвращающая стандартную разметку (HTML-строку). Это делает Enhance невероятно легким и совместимым с любой современной экосистемой.

**Единая модель для сервера и клиента.** Компоненты Enhance рендерятся на сервере как обычный HTML. При необходимости они «улучшаются» (enhanced) на клиентской стороне через Web Components (Custom Elements + Shadow DOM). Это означает, что один и тот же компонент может работать и как статический HTML, и как полноценный интерактивный элемент, в зависимости от того, подключен ли его клиентский JavaScript.

**Минимализм и стабильность.** Enhance использует возможности платформы, которые уже есть в браузере, вместо того чтобы создавать новые абстракции. Это гарантирует долгосрочную стабильность и совместимость с будущими версиями браузеров. Enhance особенно хорошо подходит для проектов, которые требуют максимальной производительности и минимального размера бандла, таких как правительственные сайты, документация и проекты с жесткими требованиями к доступности.

### Partial Islands и гранулярная гидратация

Эволюция концепции островов привела к появлению Partial Islands, выводящих оптимизацию трафика на беспрецедентный уровень. Это не просто отдельные острова — это точечная гидратация внутри островов.

**Partial Hydration (Частичная гидратация).** Вместо полной активации крупного острова современные сборщики умеют гидратировать лишь точечные поддеревья внутри него. Например, большой остров корзины может содержать: общую информацию о товарах (статичный HTML), кнопку «Удалить» (требует JavaScript) и поле для ввода промокода (требует JavaScript и валидации). Partial Hydration позволяет гидратировать только кнопку и поле ввода, оставляя остальную часть корзины без JavaScript. Это сокращает объем кода даже внутри и без того небольшого острова.

**Server Islands (Серверные острова).** Это более поздняя инновация, позволяющая инкапсулировать динамический или персонализированный контент — например, сайдбар с рекомендациями, корзину пользователя или блок с актуальными курсами валют — в виде изолированных серверных фрагментов, которые подгружаются асинхронно вообще без отправки клиентского JavaScript. Серверный остров генерирует HTML на сервере в ответ на запрос от клиента и возвращает готовый HTML-фрагмент, который браузер встраивает в страницу. Это идеально для персонализированных данных, которые известны только на сервере и требуют авторизации.

**Автоматическая оптимизация.** В 2026 году современные сборщики и фреймворки автоматически определяют, какие части острова могут быть статическими, а какие требуют гидратации, без необходимости ручной разметки. Разработчик просто пишет компонент, а инструменты сборки анализируют его код и применяют Partial Hydration автоматически, используя анализ зависимостей и статический анализ кода.

---

Islands Architecture в 2026 году — это не просто локальная техника оптимизации загрузки, а полноценная архитектурная парадигма, которая меняет способ мышления о веб-разработке. Вместо вопроса «Какой JavaScript мне нужно отправить?» разработчик задается вопросом «Какой JavaScript мне вообще нужно отправлять?» Статический HTML становится стандартом по умолчанию, а интерактивность — исключением. Это разгружает процессор клиентского устройства от рутинной работы, снижает потребление памяти, улучшает время загрузки и гарантирует пользователю максимальную отзывчивость и стабильность интерфейса, даже на медленных сетях и слабых устройствах. Astro, Fresh и Enhance — это три разных взгляда на одну и ту же идею, но все они ведут к одному и тому же: веб-платформа снова становится быстрой и легкой.
